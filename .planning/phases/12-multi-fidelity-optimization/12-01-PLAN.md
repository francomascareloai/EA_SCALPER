<critical_design_notes>
## Why This Design Avoids Selection Bias

The original plan ran stride 1 only for "TOP 10 configs chosen by stride 5/10".
This creates selection bias: correlation is computed only on the tail that stride 5 chose.

CORRECT DESIGN: Run ALL strides on the SAME random sample.
- 50 random configs (ARGUS research: n≥50 required for reliable Spearman ρ at 0.7 threshold)
- ALL 50 get stride 1, stride 5, AND stride 10
- Correlation computed on full population, not filtered subset
- MANDATORY: Join by config_id before computing correlation (prevents order mismatch)

## Why Multi-Metric Correlation

Pipeline later ranks by different metrics at each stage:
- Stage 1: PnL
- Stage 2: ProfitFactor
- Stage 3: MC95DD (proxy: MaxDD for now)

If we only validate PnL correlation, we might preserve PnL ranking while
destroying DD ranking - and DD is what kills Apex accounts.

METRICS TO VALIDATE:
1. PnL (primary)
2. MaxDD (Apex critical)
3. ProfitFactor (robustness)
4. TradeCount (consistency)

## Session-Bucket Correlation (Round 3 addition)

Beyond aggregate correlation, validate per trading session:
- ASIA (18:00-03:00 ET): Often ranging, wider spreads
- LONDON (03:00-08:00 ET): High volume, news risk
- NY (08:00-16:00 ET): Primary trading window
- OVERLAP (08:00-11:30 ET): Peak liquidity

CATASTROPHIC FAILURE GATE: If ANY session bucket has ρ < 0.4 for any metric,
the stride is flagged as UNSAFE for that session.

## Train/Holdout Split

To avoid selection-on-test leakage:
- TRAIN periods (P1, P2, P4): Used for ranking in tournament stages
- HOLDOUT periods (P3, P5): Used ONLY for final validation

This prevents overfitting to the validation set.
</critical_design_notes>

    Create analysis script that computes correlation for MULTIPLE metrics:

    ```python
    METRICS_TO_VALIDATE = ["pnl", "max_dd", "profit_factor", "trades"]

    def calculate_rank_correlations(df: pd.DataFrame) -> pd.DataFrame:
        """Calculate Spearman correlation for each metric and stride pair.

        CRITICAL: Join by config_id to ensure correct pairing (Round 3 fix).
        """
        results = []

        for metric in METRICS_TO_VALIDATE:
            for period in df["period"].unique():
                period_df = df[df["period"] == period]

                # CRITICAL: Pivot by config_id to ensure correct pairing
                pivot = period_df.pivot(
                    index="config_id",
                    columns="stride",
                    values=metric
                ).dropna()

                # Sanity check: verify we have all configs for all strides
                assert len(pivot) >= 45, f"Missing configs: only {len(pivot)} paired"

                # Get ranks from properly aligned data
                stride1_ranks = pivot[1].rank()
                stride5_ranks = pivot[5].rank()
                stride10_ranks = pivot[10].rank()

                # Compute correlations
                rho_5v1, p_5v1 = spearmanr(stride5_ranks, stride1_ranks)
                rho_10v1, p_10v1 = spearmanr(stride10_ranks, stride1_ranks)

                results.append({
                    "metric": metric,
                    "period": period,
                    "n_configs": len(pivot),  # Track sample size
                    "stride5_vs_stride1_rho": rho_5v1,
                    "stride5_vs_stride1_p": p_5v1,
                    "stride10_vs_stride1_rho": rho_10v1,
                    "stride10_vs_stride1_p": p_10v1,
                })

        return pd.DataFrame(results)
    ```
