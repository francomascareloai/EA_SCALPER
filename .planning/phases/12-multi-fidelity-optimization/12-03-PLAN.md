<apex_compliance_gates>
## MANDATORY ELIMINATION CRITERIA (Applied at EVERY Stage)

These are not relative rankings - these are ABSOLUTE floors. Any config violating
these is immediately disqualified, regardless of how it ranks against others.

```python
@dataclass
class ApexComplianceGate:
    """Hard constraints that cannot be violated."""

    # Apex trailing DD limit (5% from HWM including unrealized)
    max_trailing_dd_pct: float = 4.0  # Safety buffer below 5% kill switch

    # Daily DD limit
    max_daily_dd_pct: float = 3.0  # Conservative daily limit

    # Minimum trades to be statistically meaningful
    min_trades: int = 5  # Per period minimum

    # Minimum profit factor (must be profitable)
    min_profit_factor: float = 1.0  # At least break-even

    # TIME GATE COMPLIANCE (CRUCIBLE Round 2 fix)
    enforce_time_gates: bool = True

    def check(self, result: BacktestResult) -> tuple[bool, Optional[str]]:
        """Return (passed, reason_for_failure)."""
        if result.max_trailing_dd_pct >= self.max_trailing_dd_pct:
            return False, f"Trailing DD {result.max_trailing_dd_pct:.1f}% >= {self.max_trailing_dd_pct}%"

        if result.max_daily_dd_pct >= self.max_daily_dd_pct:
            return False, f"Daily DD {result.max_daily_dd_pct:.1f}% >= {self.max_daily_dd_pct}%"

        if result.total_trades < self.min_trades:
            return False, f"Only {result.total_trades} trades < {self.min_trades} minimum"

        if result.profit_factor < self.min_profit_factor:
            return False, f"Profit factor {result.profit_factor:.2f} < {self.min_profit_factor}"

        # TIME GATE CHECKS (ROUND 5 FIX: ABSOLUTE ZERO tolerance)
        if self.enforce_time_gates:
            if result.positions_after_459pm > 0:
                return False, f"{result.positions_after_459pm} positions held past 4:59 PM ET"
            # CRITICAL: Apex blocks ALL new trades after 4:30 PM ET (not a percentage)
            if result.trades_after_430pm > 0:
                return False, f"APEX VIOLATION: {result.trades_after_430pm} trades after 4:30 PM block"

        return True, None
```

WHY these thresholds:
- Trailing DD 4.0%: Buffer below Apex 5% kill switch
- Daily DD 3.0%: Conservative intraday limit
- Min trades 5: Need enough samples for statistical validity
- Min PF 1.0: Don't promote losing configs even if "least bad"

    from enum import Enum
    from dataclasses import dataclass

    class FidelityStage(Enum):
        STAGE_0_SANITY = 0    # Stride 20 - bug detection, sanity check
        STAGE_1_FILTER = 1    # Stride 10 - filter 80% garbage by ranking
        STAGE_2_REFINE = 2    # Stride 5  - refine top 20% by robust metrics
        STAGE_3_VALIDATE = 3  # Stride 1  - validate top 5-10 finalists

    @dataclass
    class StageConfig:
        stage: FidelityStage
        stride: int
        promotion_pct: float  # Top X% promoted to next stage
        min_configs: int      # Minimum configs to promote regardless of %
        ranking_metric: str   # Metric to rank by (pnl, sharpe, dd, pf)

    STAGE_CONFIGS: dict[FidelityStage, StageConfig] = {
        FidelityStage.STAGE_0_SANITY: StageConfig(
            stage=FidelityStage.STAGE_0_SANITY,
            stride=20,
            promotion_pct=1.0,  # All pass (just sanity check)
            min_configs=100,
            ranking_metric="pnl"
        ),
        FidelityStage.STAGE_1_FILTER: StageConfig(
            stage=FidelityStage.STAGE_1_FILTER,
            stride=10,
            promotion_pct=0.2,  # Top 20%
            min_configs=20,
            ranking_metric="pnl"
        ),
        FidelityStage.STAGE_2_REFINE: StageConfig(
            stage=FidelityStage.STAGE_2_REFINE,
            stride=5,
            promotion_pct=0.25,  # Top 25% of remaining
            min_configs=10,
            ranking_metric="profit_factor"  # More robust than PnL
        ),
        FidelityStage.STAGE_3_VALIDATE: StageConfig(
            stage=FidelityStage.STAGE_3_VALIDATE,
            stride=1,
            promotion_pct=1.0,  # Final stage - all are finalists
            min_configs=5,
            ranking_metric="mc95_dd"  # Monte Carlo worst-case DD
        ),
    }
    ```

    WHY these promotion rates:
    - Stage 0→1: 100% (sanity check only, fast)
    - Stage 1→2: 20% (aggressive filter, cheap)
    - Stage 2→3: 25% of 20% = 5% of original (10-20 configs)
    - Final: 5-10 configs validated at stride 1

    WHY profit_factor at stage 2: More robust than pure PnL, less noisy.
    WHY mc95_dd at stage 3: Apex DD is the real constraint, optimize for survival.

            ...

        def promote(self, stage: FidelityStage, results: pd.DataFrame) -> list[StrategyConfig]:
            """Select top configs for promotion to next stage."""
            stage_config = STAGE_CONFIGS[stage]
            n_promote = max(
                int(len(results) * stage_config.promotion_pct),
                stage_config.min_configs
            )
            top_results = results.nlargest(n_promote, stage_config.ranking_metric)
            return [self._result_to_config(r) for r in top_results.itertuples()]

        def run_tournament(self) -> pd.DataFrame:
            """Run full multi-fidelity tournament."""
            current_configs = self.config_grid

            for stage in FidelityStage:
                print(f"Stage {stage.name}: {len(current_configs)} configs @ stride {STAGE_CONFIGS[stage].stride}")

                results = self.run_stage(stage, current_configs)
                self.results[stage] = results
                self._save_stage_results(stage, results)

                if stage != FidelityStage.STAGE_3_VALIDATE:
                    current_configs = self.promote(stage, results)

            return self.results[FidelityStage.STAGE_3_VALIDATE]

        def _save_stage_results(self, stage: FidelityStage, results: pd.DataFrame) -> None:
            """Persist stage results for later analysis."""
            ...
    ```

    WHY save each stage: Allows resumption if interrupted, audit trail for analysis.
    WHY tournament pattern: Industry standard for expensive optimization (DAEMON recommendation).
