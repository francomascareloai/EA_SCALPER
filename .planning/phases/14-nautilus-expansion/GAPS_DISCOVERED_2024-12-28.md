# AREA 1: RISK/POSITION MANAGEMENT

## Gap R1: TradingState Risk Control (REDUCING/HALTED) - CRITICAL ⚠️ BROKEN

**STATUS: ⚠️ BROKEN** - Code exists at `base_strategy.py:1497` but does NOT work.

- **What it does**: RiskEngine supports three TradingState modes that control order flow at the engine level:
  - `ACTIVE`: Normal operation (all orders allowed)
  - `REDUCING`: Only position-reducing orders allowed (closes + cancels)
  - `HALTED`: All orders blocked except cancels
- **Source**: `/external/nautilus_trader/crates/risk/src/engine/mod.rs:508-527`, `/external/nautilus_trader/docs/concepts/execution.md:135-140`
- **Why we should use it**: Perfect for Apex DD compliance. When trailing DD hits 4.0%, set state to `REDUCING` to prevent new positions while allowing emergency closes. At 4.5% set to `HALTED`.

### Root Cause (FORGE verified via introspection)
Current code assumes `self.trader.risk_engine` exists:
```python
# base_strategy.py:1511 - THIS DOESN'T WORK
def _set_trading_state(self, state: TradingState, reason: str) -> None:
    trader = getattr(self, "trader", None)
    if trader is not None:
        risk_engine = getattr(trader, "risk_engine", None)  # ← DOESN'T EXIST!
        if risk_engine is not None:
            risk_engine.set_trading_state(state)
```
In NautilusTrader 1.221.0, `Strategy` has NO `risk_engine`, `kernel`, or `system` accessor.

### Solution (FORGE recommended)
Inject RiskEngine handle from BacktestEngine layer in `run_backtest.py`:
```python
# After strategy instantiation, before engine.run():
strategy._risk_engine = engine.kernel.risk_engine

# Then in base_strategy.py:
def _set_trading_state(self, state: TradingState, reason: str) -> None:
    if hasattr(self, "_risk_engine") and self._risk_engine is not None:
        self._risk_engine.set_trading_state(state)
        self.log.warning(f"TradingState → {state.name}: {reason}")
```

### CRITIC Warning: HALTED may block exit orders!
RiskEngine `HALTED` denies ALL `SubmitOrder` including exits. Verify emergency flatten
orders still work under `REDUCING` before using `HALTED` while in-position.

- **Integration effort**: MEDIUM (requires engine-layer wiring)
- **Priority**: CRITICAL (Apex safety - currently illusory protection)
